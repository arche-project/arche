## Décisions prises en cours de route

1. **`journal_mode = TRUNCATE`, pas `MEMORY`** (l'ADR disait `MEMORY`). Avec un journal en mémoire,
   un processus tué au milieu d'une transaction corrompt le fichier — exactement le cas « SIGTERM au
   milieu » du critère 2. Un journal remis à l'OS (`synchronous = OFF`) survit à la mort du processus
   (SQLite le garantit) et ne coûte rien de mesurable par lot de 50 articles. La coupure de courant
   reste le cas « fichier jetable » : une base illisible est supprimée et reconstruite. L'ADR est
   amendé.
2. **Un article et ses chunks dans la même transaction** ; la reprise saute les articles présents
   (`articles.path`) plutôt que de lire `max(ordinal)` par article : atomicité par article, aucun
   chunk orphelin possible, et un `SELECT 1 WHERE path = ?` par article à la ré-extraction (rapide).
   L'embedding reprend de `max(chunk_id)` (les vecteurs sont insérés dans l'ordre des ids, commis
   par lots) ; `count(*)` le recoupe. Les `UNIQUE` du schéma rendent le doublon impossible.
3. **Une base finie du même corpus est reconstruite, pas « reprise »** : `index build` est un ordre
   explicite ; la reprise ne vaut que pour une base incomplète (sans `built_at`) du même
   `resource_id`. Un fichier d'un autre corpus est écrasé.
4. **L'estimation mesure au lieu de deviner** : découper et insérer dans une base en mémoire (texte
   + FTS5 réels) coûte quelques secondes par centaine de Mo et donne ±5 % ; l'ordre de grandeur par
   Go n'est gardé que pour les ZIM (dump complet nécessaire) et les ressources non installées, et
   la sortie dit toujours laquelle des trois bases de calcul a servi.
5. **Filtre de l'avertissement dans `cli.ts`**, pas `--no-warnings` dans un lanceur (un shebang ne
   porte pas de flag Node, et le SEA non plus) : `process.removeAllListeners('warning')` + un
   écouteur qui laisse passer tout sauf l'`ExperimentalWarning` de SQLite. Efficace avec `node
   dist/cli.js` ; sous `tsx` l'avertissement est émis au chargement (async) avant le premier code
   évalué — bruit de développement seulement, dit dans l'ADR.
6. **Soustraire ce que le ticket remplace, pas seulement cesser de l'écrire** : « remplace
   .arche-idx + index/text » ⇒ les lecteurs de `index/text/` (canal `local` BM25 maison,
   `readLocalArticle` dans MCP) et `bm25.ts` + `tokenize` partent avec, `writeShard` aussi.
   C'était aussi la seule façon de tenir sous le seuil CI de 7 000 lignes (le writer seul mettait
   `src/` à 7 127). Le lecteur `.arche-idx` et `assertFusable` restent jusqu'à M1-3, qui les
   supprime (les critères de M1-3 restent vrais : « parseurs de .arche-idx et BM25 maison
   supprimés » — le BM25 l'est déjà). Le test de chaîne complète (build → BM25 local → MCP
   `read_article` sur `index/text/`) est remplacé, pas seulement adapté : ce qu'il testait n'existe
   plus ; le trajet complet sur SQLite est le test de M1-3.
7. **`url` des articles = `arche://article/<resource_id>/<path>` pour tous** (ZIM compris) : c'est
   l'URI que le serveur MCP expose déjà, et que M1-3 servira depuis `articles`/`chunks` ; le lien
   kiwix-serve se reconstruit du `path`.
8. **Documents de l'utilisateur** : `license_spdx = NOASSERTION` (vocabulaire SPDX pour « rien
   d'affirmé »), `license_redistribution = forbidden`, `languages = mul`, jamais de `.zst` — ils ne
   sortent pas du disque (ADR 0014, « jamais publié »).
9. **`build.sh` adapté a minima** (nom de fichier, `.zst` si présent, champs du résultat) pour que la
   CI appelle la CLI cohérente ; `upload-ia.sh` (licence « MIT » sur un dérivé — erreur 8 de l'audit)
   et `update-catalog.ts` (ancien bloc `index`) sont laissés à M1-10, qui redéfinit le bloc.
10. **Le test SIGTERM tue un vrai processus** (`spawn` + `kill('SIGTERM')`) plutôt que de simuler :
    c'est le seul moyen de prouver que le journal SQLite fait son travail. Le faux embedder est
    ralenti (150 ms par lot) et commet tous les deux lots pour que le signal tombe **pendant une
    transaction ouverte** : le test vérifie que ce lot-là est annulé et que les précédents restent.

### Critères

1. **`index build <id> --out x.arche.sqlite` → base ouvrable par sqlite3 avec les 5 tables — tenu.** Reproduit hors test par la CLI compilée et relu avec le module `sqlite3` de Python (ci-dessus) ; `tests/index.test.ts` `ok 3` fait la même chose avec la fixture (5 tables + `vectors_fake_64`, six clés `meta`, FTS5 sans accents, `assets`, vecteurs int8 de `dims` octets, cosinus > 0,98). Code : `src/core/rag/build.ts` `buildShard` (schéma posé par `openCorpus` de `sqlite.ts`, ADR 0014).
2. **Build interrompu (SIGTERM) reprend au dernier lot sans doublon — tenu.** `ok 4`, relancé 3 fois : (a) embedder qui tombe après un lot commis → relance saute les 3 articles, `emb.calls = ceil((chunks − 32)/32)`, empreinte identique à une construction d'une traite ; (b) **vrai processus** (`tests/helpers/build-child.ts`, `spawn` + `kill('SIGTERM')` pendant un lot ouvert) → `partial % 64 === 0` (lot ouvert annulé par le journal `TRUNCATE`), relance = `ceil((chunks − partial)/32)` appels, même empreinte ; (c) base finie ou d'un autre corpus → reconstruite.
