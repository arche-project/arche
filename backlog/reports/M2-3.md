Date : 2026-09-12 · Taille : S · Colonne : M2 · Confiance · Dépend de : aucune.
Audit, erreur 7 : « `catalog-automerge.yml` fusionne seul les PR qui changent `source.url` et
`checksum` — précisément les deux champs qu'un attaquant veut changer ». Décision 5 de l'audit :
« aucun automerge d'URL ou de hachage ».

## Ce qui n'a pas pu être fait, et pourquoi

- **Pas d'exécution réelle des workflows** : le bac à sable n'a ni GitHub Actions ni dépôt git ;
  la logique du script est testée hors ligne, les workflows sont validés comme YAML et par les
  tests de contenu. Le premier run réel de `catalog-update.yml` (M0-2) montrera la section en tête
  de PR et l'étiquette.
- **La protection de branche « deux approbations sur `catalog-sensitive` »** ne se configure pas
  depuis un fichier du dépôt ; CONTRIBUTING.md dit qu'elle est posée dès qu'un second curateur
  existe. Avec un seul mainteneur aujourd'hui, la règle est humaine (il ouvre l'URL et recoupe le
  hachage avant de fusionner), pas mécanique — dit honnêtement dans le texte.

## Décisions prises en cours de route

1. **Périmètre des champs sensibles plus large que « url / checksum »** : le ticket dit « url,
   checksum, size, licence » ; j'ai pris `source.*` en entier (un `kind`, un `ia_item`, un
   `magnet` ou un `torrent` changé redirige le téléchargement aussi sûrement qu'une URL) et les
   trois champs de téléchargement du bloc `index` (les shards sont ce qu'on télécharge le plus).
   `index.model` / `index.dims` ne sont pas sensibles. La liste est une constante exportée et
   testée (`SENSITIVE_PREFIXES`).
2. **Ajout = sensible, retrait = signalé** : une ressource ajoutée apporte une URL et un hachage
   neufs — c'est la même relecture. Un retrait n'introduit rien à télécharger ; il reste dans le
   tableau pour que le relecteur le voie.
3. **Une PR robot ne déclenche pas `catalog-review.yml`** (GitHub n'enchaîne pas les workflows
   sur les événements créés par `GITHUB_TOKEN`) : c'est pourquoi `catalog-update.yml` calcule
   l'étiquette lui-même, et `zim-build.yml` / `index-build.yml` la posent d'office. L'ancien job
   `classify` avait le même angle mort sans le dire.
4. **`peter-evans/create-pull-request` ajoute des étiquettes, n'en retire pas** : une PR
   `catalog/auto-update` devenue non sensible à un run suivant garde l'étiquette. Le sens de
   l'erreur est le bon (trop de relecture plutôt que pas assez) ; noté ici plutôt qu'ajouter du
   code.
5. **Le script signale, ne bloque pas** (code de sortie 0) : bloquer la CI sur un changement d'URL
   empêcherait l'updater de faire son travail (les URL Kiwix datées changent chaque mois) ; ce qui
   doit être impossible, c'est la fusion sans humain, et ça l'est désormais par absence de tout
   code de fusion.
6. **Pas d'ADR** : la décision est celle de l'audit (décision 5), déjà reprise dans
   ORCHESTRATION.md (jalon M2) et PUBLICATION.md ; aucun ADR ne prévoyait l'automerge (il vivait
   dans COMMUNAUTE.md, corrigé). Le script est dans `scripts/`, pas dans `src/` : il sert la CI
   du catalogue, pas la base hors ligne, et ne pèse pas sur le noyau (ADR 0013, décision 4 de
   l'audit).
7. **Docs EN éditées aussi** (COMMUNITY, FRESHNESS, BLIND-SPOTS, paragraphe EN de CONTRIBUTING) :
   D22, les deux arbres en parallèle jusqu'à M3-5.
