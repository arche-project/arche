## Décisions prises en cours de route

1. **`meta` en clé/valeur, pas en colonnes.** Le ticket liste les champs (resource_id, sha256,
   licence, langue, built_at, version) ; ils sont tous là comme clés obligatoires, plus des clés
   conseillées (`source_kind`, `attribution`, `title`, `chunker`…). Une nouvelle métadonnée n'est
   jamais une migration.
2. **`dims` et `dtype` dans un registre `vectors`, pas par ligne.** Le ticket écrit
   `vectors_<model>(chunk_id, dims, blob, norme)` ; répéter `dims` sur 4,5 millions de lignes ne sert
   à rien, et M1-9 dit « le format porte dims et type **par table** » — c'est exactement la ligne du
   registre. La colonne `norm` est gardée (norme L2 avant normalisation, NULL si inconnue). Le
   lecteur ne devine jamais un nom de table : il lit `vectors."table"`.
3. **Le locator est une colonne calculée par une vue (`passages.locator` =
   `resource_id/path#byte_offset`)**, pas une colonne stockée : même forme que l'identifiant actuel
   de `retrieve.ts`, rien de dupliqué, et c'est ce vers quoi `knowledge/` pointera (audit, décision 2).
   Les colonnes s'appellent `byte_offset`/`byte_length` (pas `offset`, mot-clé SQL).
4. **FTS5 en contenu externe (`content='chunks'`) avec triggers** : le texte n'est stocké qu'une fois,
   et une base modifiée avec `sqlite3` reste cohérente (test sur suppression). Tokenizer
   `porter unicode61 remove_diacritics 2` : Porter est anglais, FTS5 n'a pas de racinisation
   française ; l'ADR le dit et renvoie à `arche eval` (M1-7) pour mesurer, `trigram`/Snowball vendu
   comme options si la perte est réelle. Vérifié : « deshydratation » trouve « déshydratation ».
5. **Pas d'extension vectorielle** (`sqlite-vec`) : un binaire natif par plateforme à maintenir dix
   ans ; le cosinus est un produit scalaire d'entiers dans le langage hôte (dix lignes de Python
   dans l'ADR, exécutées par le test). Les blobs sont dans un format qu'un `vec0` local pourrait
   indexer plus tard.
6. **Un module de 65 lignes dans `src/`, pas zéro.** Le schéma doit avoir une source de vérité
   exécutable pour que M1-2 ne le recopie pas et que le test ADR ⇔ code existe. `src/` passe de
   6 934 à 6 999 lignes — un cheveu sous le seuil CI de 7 000, assumé : M1-3 supprime `shard.ts`
   (172) et `bm25.ts` (67), le solde du chantier M1 est négatif. Le bloc du README est rafraîchi.
7. **Fichier compagnon de vecteurs** (`<id>.vectors.<modèle>.arche.sqlite.zst`, `ATTACH` + copie) :
   décidé dans l'ADR parce que « ajoutable sans republier le texte » n'a de sens à l'échelle de cent
   corpus que si le nouveau modèle se publie sans retransférer le texte. M1-4/M1-10 l'implémentent.
8. **ADR 0007 amendé en place** (une ligne sous son statut) plutôt que réécrit : ses points 3, 5, 8
   sont remplacés, le reste tient — c'est ce que dit aussi l'audit.
9. **La fixture est construite par le test**, pas déposée dans `tests/fixtures/` : 3 articles, 4
   chunks, 64 dimensions, supprimée après ; rien à maintenir. Le `.arche.sqlite` doit exister sur
   disque le temps du test pour que Python et `sqlite3` l'ouvrent sans Arche — c'est le point.
