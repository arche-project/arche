# Rapport M3-1 — Mesurer le noyau : scripts/loc.sh, seuil CI à 3 000 lignes dans src/

Date : 2026-09-12 · Taille : S · Dépend de : aucune · Débloque : M3-2, M3-3.

## Ce qui a été fait

- **`scripts/loc.sh`** (nouveau, 101 lignes) : compte les lignes de code TypeScript/JavaScript
  (`.ts .tsx .js .mjs .cjs`) de `src/`, `examples/` et `vendor/` séparément, hors `*.test.ts`,
  `*.d.ts`, `node_modules/`, `fixtures/`, `dist/`, et hors tout ce qui n'est pas du code (HTML,
  YAML, Markdown, JSON). Options : `--max N` (échoue, code 1, si `src/` dépasse N — l'appel de la
  CI), `--readme` (réécrit le bloc `<!-- loc --> … <!-- /loc -->` du README, et rien d'autre),
  `--root DIR` (mesure une autre arborescence — les tests). Bash 3.2, aucune commande externe hors
  `wc` (pas de `find`, `sed`, `awk`) : le même script tourne sous Linux, macOS et Git Bash, donc
  sur les trois OS de la matrice CI.
- **`package.json`** : script `loc` → `bash scripts/loc.sh`.
- **`.github/workflows/ci.yml`** : étape « Core size (src/ ≤ 7000 lines) », `shell: bash`,
  `bash scripts/loc.sh --max 7000`, avec le calendrier en commentaire (7 000 → 5 000 après M3-3 →
  3 000 après M3-6 ; jamais remonté).
- **`README.md`** : paragraphe « Le noyau se mesure » avec le bloc `<!-- loc -->` rempli par le
  script (`src/` 6934 · `examples/` 0 · `vendor/` 0), la cible (3 000), le seuil courant (7 000) et
  son calendrier ; lien vers la doc dans la liste « Documentation ».
- **`docs/fr/NOYAU.md`** (nouveau) : ce qu'on compte et pourquoi, le calendrier du seuil, comment
  publier le chiffre, les options.
- **`tests/loc.test.ts`** (nouveau, 5 tests) : arborescence minuscule créée à la volée dans un
  dossier temporaire (pas de fixture dans le dépôt) — comptage séparé et exclusions ; `--max` qui
  échoue au-dessus et passe au seuil exact ; `--readme` qui ne touche que le bloc, idempotent, et
  refuse (code 2) sans marqueurs ; recoupement du chiffre de `src/` sur le dépôt réel avec un
  compte indépendant écrit en Node ; cohérence ci.yml ↔ README ↔ script (le seuil de ci.yml est
  dans {7000, 5000, 3000}, le README porte le bloc, et `src/` passe sous le seuil courant). Sans
  bash (ENOENT), les tests qui l'exécutent sont sautés au lieu d'échouer.

`src/` n'a pas bougé : 6 934 lignes, le chiffre exact de l'audit — c'est le point de départ.

## Ce qui n'a pas pu être fait, et pourquoi

- Le seuil final de 3 000 n'est **pas** appliqué aujourd'hui : le ticket le dit lui-même
  (« au-dessus de 3 000 une fois M3-2/M3-3/M3-6 faits »). À 6 934 lignes, un seuil à 3 000 rendrait
  la CI rouge sur chaque commit sans rien mesurer. La CI applique donc le premier palier, 7 000 ;
  M3-3 passe à 5 000 et M3-6 à 3 000 (leurs critères d'acceptation le disent), en éditant une ligne
  de ci.yml et la phrase du README. Le test refuse tout seuil hors de {7000, 5000, 3000}.
- La CI n'a pas été exécutée (pas de dépôt GitHub encore, M0). L'étape est écrite pour les trois
  OS (`shell: bash` ; le script évite `find`, dont l'homonyme Windows piège les shells non-bash).

## Décisions prises en cours de route

1. **Ce qu'on compte** : TypeScript/JavaScript seulement, hors tests. Le chiffre de l'audit
   (« 6 934 lignes de TypeScript dans src/ ») est la référence dont on part ; compter aussi
   `src/web/static/index.html` (209 lignes) aurait donné 7 143, au-dessus du premier palier, pour
   un fichier qui n'est pas du logiciel au sens du critère ADR 0013. Les tests ne comptent pas :
   on ne veut pas décourager d'en écrire. `vendor/` est compté à part, visible, jamais plafonné :
   vendre plutôt que réécrire a un coût, on l'affiche.
2. **Bash, pas Node**, parce que le ticket nomme `scripts/loc.sh` et que c'est l'option la plus
   petite ; mais bash 3.2 (macOS) et sans `find`/`sed`/`awk` pour que la CI Windows (Git Bash) et
   macOS passent sans variante. Le test préfère `C:\Program Files\Git\bin\bash.exe` sous Windows
   (le `bash` de System32 est le lanceur WSL).
3. **Le README n'est pas vérifié en CI** : un chiffre en retard dans le README n'est pas une
   régression, un dépassement l'est. Le bloc se rafraîchit par `npm run loc -- --readme` (à faire
   avec chaque ticket M3 et à chaque release) ; le test vérifie seulement que le bloc existe et
   que la CI reste verte au seuil courant.
4. **Pas de fixture dans le dépôt** : l'arborescence de test est créée dans un dossier temporaire
   et supprimée — rien à maintenir, rien à compter par erreur (`fixtures/` est de toute façon exclu).
5. **Doc** : une page courte `docs/fr/NOYAU.md` plutôt qu'une section noyée dans ARCHITECTURE.md,
   pour que le calendrier du seuil soit trouvable depuis le README. Pas de version EN (D22 non
   tranchée) ; pas d'ADR : le ticket applique la décision 4 de l'audit, il n'en change aucune.
